# Guide Map Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Guide map" tab in the web UI that draws the plan's GeoJSON on an OpenStreetMap street map, with an Import button to open other plans' `.geojson` files.

**Architecture:** A pure parser (`src/lib/geo.ts`, unit-tested) turns GeoJSON text into a `TripMap` (stay + stops grouped by day). A `GuideMap` component owns a plain Leaflet map in a `useEffect`, plus a plan switcher/import row and a stop list. `App.tsx` adds the tab.

**Tech Stack:** React 19, TypeScript 5.8, Vite 7, Vitest 3 (node environment, `src/**/*.test.ts` only), `leaflet` + `@types/leaflet`.

**Spec:** `docs/superpowers/specs/2026-11-19-guide-map-design.md`

## Global Constraints

- No backend change; no new state keys. Source of the current plan's map: `run.state.guide_exports.map` (a string).
- Plain `leaflet`, not `react-leaflet`. Tiles: `https://tile.openstreetmap.org/{z}/{x}/{y}.png` with attribution `&copy; <a href="https://www.openstreetmap.org/copyright">OpenStreetMap</a> contributors`.
- Markers are `L.divIcon`s (no Leaflet default marker images).
- Imported maps live in memory only; same file name re-imported replaces that entry.
- Tab label is exactly `Guide map`, placed right after `Guide`.
- **Never commit or stage.** The user does all git commits. Where a step says "checkpoint", stop and leave the changes in the working tree.
- Copy style: short plain sentences, like the existing empty states in `Panels.tsx`.

## Review Focus

1. **Text from GeoJSON goes into popup HTML.** A place name like `<img onerror=…>` in an imported file must render as text. → `escapeHtml` test in Task 1; popups built only through it.
2. **Imported file is not our format** (a Polygon-only file, a bare Feature, `[]`, invalid JSON). → Expect an inline error and the previous map unchanged. → `parseTripMap` rejection tests in Task 1.
3. **Points without `order`/`day`** (GeoJSON from another tool). → Still drawn, as one group "Other places", in file order. → Test in Task 1.
4. **Switching between plans / a new run arriving.** Old markers and lines must not linger; the map must refit. → Task 2 removes the layer group and refits on every `TripMap` change (manual check step).
5. **Map in a hidden tab or resized container** renders grey/half-drawn. → Task 2 calls `map.invalidateSize()` after mount and after fit (manual check step).

### Task 1: GeoJSON parser

**Files:**
- Create: `travel-planner-ui/src/lib/geo.ts`
- Test: `travel-planner-ui/src/lib/geo.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export interface MapStop { order: number | null; day: number | null; date: string | null; time: string | null;
    kind: string | null; name: string; url: string | null; lat: number; lon: number }
  export interface MapDay { day: number | null; date: string | null; stops: MapStop[] }   // day null = "Other places"
  export interface TripMap { stay: MapStop | null; days: MapDay[] }
  export function parseTripMap(text: string): TripMap          // throws Error with a user-facing message
  export function escapeHtml(s: string): string
  ```

- [ ] **Step 1: Write the failing tests** in `geo.test.ts`, using a fixture built from the real Lisbon file (`output/lisbon-2027-05-10-to-2027-05-14.geojson`: stay + 6 stops on days 2, 2, 3, 3, 3, 4):
  - `parses the stay and groups stops by day`: `stay.name === "Cantinho dos Pacatos - Bunk bed (red)"`, `stay.lat === 38.7471`, `stay.lon === -9.1331` (GeoJSON is `[lon, lat]`); `days.map(d => d.day)` equals `[2, 3, 4]`; `days[1].stops.map(s => s.order)` equals `[3, 4, 5]`.
  - `orders stops within a day by order even if the file is shuffled`.
  - `puts points without day into one null-day group after the numbered days, in file order`, with `name` falling back to `"Unnamed place"` when missing.
  - `rejects invalid JSON` → throws `/not valid JSON/`.
  - `rejects GeoJSON with no points` (a FeatureCollection with only a Polygon, and `{"type":"Feature",...}`, and `[]`) → throws `/no places/`.
  - `skips features with non-numeric coordinates` (e.g. `["a", 1]`) without throwing if another point is valid.
  - `escapeHtml escapes & < > " '`: `escapeHtml('<b a="x">&\'')` equals `'&lt;b a=&quot;x&quot;&gt;&amp;&#39;'`.

- [ ] **Step 2: Run to verify they fail**

  Run: `npx vitest run src/lib/geo.test.ts` (in `travel-planner-ui/`)
  Expected: FAIL (cannot resolve `./geo`).

- [ ] **Step 3: Implement `parseTripMap` and `escapeHtml` in `geo.ts`.** A feature with `properties.kind === "stay"` is the stay (first one wins); every other Point is a stop. Error messages: `"This file is not valid JSON."` and `"This file has no places to show on a map."`. Only `FeatureCollection` input is accepted (anything else → the "no places" error).

- [ ] **Step 4: Run to verify they pass**

  Run: `npx vitest run` → all tests pass, including the existing `run.test.ts`.

- [ ] **Step 5: Checkpoint.** Leave changes uncommitted for the user.

### Task 2: GuideMap component, tab and dependency

**Files:**
- Modify: `travel-planner-ui/package.json` (via `npm install leaflet` and `npm install -D @types/leaflet`)
- Create: `travel-planner-ui/src/components/GuideMap.tsx`
- Modify: `travel-planner-ui/src/App.tsx:4,26-34,192,198` (import, `Tab` union, `TABS`, ready dot, panel)
- Modify: `travel-planner-ui/src/components/Panels.tsx:103` (tooltip: `"The planned places in visiting order; open it in geojson.io, uMap or QGIS"`)
- Modify: `travel-planner-ui/src/styles.css` (append a `/* guide map */` block)

**Interfaces:**
- Consumes: `parseTripMap`, `escapeHtml`, `TripMap`, `MapStop` from Task 1.
- Produces: `export interface ImportedMap { name: string; text: string }` and
  `export function GuideMapPanel({ run, imports, onImport }: { run: RunState; imports: ImportedMap[]; onImport: (m: ImportedMap) => void }): JSX.Element` in `GuideMap.tsx`.
  The imports list lives in `App` because `App` unmounts a tab's panel when another tab is opened.

- [ ] **Step 1: Install the dependency.** In `travel-planner-ui/`: `npm install leaflet` and `npm install -D @types/leaflet`. Import `leaflet/dist/leaflet.css` at the top of `GuideMap.tsx`.

- [ ] **Step 2: Implement `GuideMapPanel`.**
  - Local state: `selected: "run" | string` (an import name), `error: string`. `imports` comes from props.
  - Current source text: `selected === "run"` → `run.state.guide_exports?.map`; else the import's text. Parse with `useMemo(parseTripMap)`, catching errors (a broken current-run map shows the error text, not a crash).
  - When the current run's map first appears or changes, keep `selected` as is. If `selected` names an import that no longer exists, fall back to `"run"`.
  - **Switcher row** (class `map-sources`): a `<select>` listing `This run's plan` (only when the run has a map) then imports by file name, and an `Import map file` button that clicks a hidden `<input type="file" accept=".geojson,application/geo+json,application/json">`. On file pick: read text, `parseTripMap` it; on error set `error` and change nothing; on success call `onImport({ name, text })` and select it (App upserts by name). Show `error` in `<span className="error-text" role="alert">`.
  - **Empty state:** no run map and no imports → the existing empty-state wording style: `"The map of the planned places appears here when the guide writer has saved the guide. You can also open a .geojson map file of another plan."` plus the Import button.
  - **Map:** a `div.guide-map` ref. One effect creates `L.map` + the OSM tile layer once (cleanup `map.remove()`). A second effect, on each `TripMap` change, removes the previous `L.layerGroup` and adds a new one:
    - Stay: `divIcon` with class `pin pin-stay` and content `⌂`.
    - Stops: `divIcon` with class `pin`, content = `order` (or `•` if null), `style="background:<day colour>"`.
    - Day colours cycle `--line-transport, --line-stay, --line-culture, --line-food, --line-review` (resolve with `getComputedStyle(document.documentElement)`); the null-day group uses `--ink-3`.
    - One `L.polyline` per day with ≥2 stops, same colour, weight 3, opacity 0.8.
    - Popup HTML built only from `escapeHtml(...)` values: name (bold), `Day N · date · time`, kind, and a link (`target="_blank" rel="noopener noreferrer"`) only if `url` starts with `http://` or `https://`.
    - `map.fitBounds(allPoints, { padding: [30, 30], maxZoom: 15 })`, then `map.invalidateSize()`.
    - Keep a `Map<MapStop, L.Marker>` ref for the list.
  - **Stop list** (class `map-stops`) under the map: per day a heading (`Day N` with a colour dot, date if any; `Other places` for null day) and buttons `① Name · time`; clicking calls `map.setView(marker.getLatLng(), Math.max(map.getZoom(), 15))` and `marker.openPopup()`. The stay is listed first as `⌂ Name`.
  - **Note** under the map: `"Street map tiles come from OpenStreetMap and need an internet connection; the pins work offline."` (class `muted`).

- [ ] **Step 3: Wire the tab in `App.tsx`.** Add `const [mapImports, setMapImports] = useState<ImportedMap[]>([])` with an `onImport` that replaces an entry of the same name or appends. Add `"map"` to `Tab`, `{ id: "map", label: "Guide map" }` after guide in `TABS`, the `tab-dot` when `typeof (run.state.guide_exports as any)?.map === "string"`, and `{tab === "map" && <GuideMapPanel run={run} imports={mapImports} onImport={...} />}`. Update the `Panels.tsx:103` tooltip.

- [ ] **Step 4: Styles.** `.guide-map { height: 420px; border: 1px solid var(--rule); border-radius: 8px; }`; `.pin` a 26px round white-bordered badge with centred bold white number (Leaflet `divIcon` `iconSize: [26, 26]`, `iconAnchor: [13, 13]`, `className` set so Leaflet's default white box is not used); `.pin-stay` dark (`var(--ink)`) and slightly larger; `.map-sources` flex row with gap like `.guide-actions`; `.map-stops` compact list. Popup text uses `var(--font)`.
