# Open data closes two of four gaps

Free, no-card sources can replace Tavily for **two gaps outright: traditional dishes and museum opening hours**. For **fares, ticket prices and restaurant ratings**, web search still has to sit behind the new tools. **Dishes** are the clearest win: the Wikivoyage country "Eat" section, which the planner's MediaWiki client can already fetch, names the canonical dishes for Portugal, Estonia and Finland. Wikidata SPARQL adds canonical names, images and a popularity ranking. **Opening hours** come next: OSM `opening_hours` is filled for 63–82% of museums in Lisbon, Tallinn and Helsinki. Helsinki's city APIs add day-by-day hours that include holidays. **Ground fares** are only partly covered. Two keyless official MCP servers, Virail and Ferryhopper, return real prices, but in live tests neither covered Helsinki–Tallinn ferries, Finnish rail or Portuguese rail reliably. **Restaurant ratings** have no free, no-card, ToS-clean source at all: Google Places is the only strong option, and it needs a billing account. The notes disagree about Tripadvisor; the more specific and more recent claim wins, and it rules Tripadvisor out. In short, change Tavily from the default tool into a fallback. Add four no-card tools (Virail/Ferryhopper MCP, Wikivoyage+Wikidata dishes, OSM hours with a Helsinki Hauki branch, and Wikivoyage/Michelin price tiers). Treat Google Places as the one optional upgrade that needs a card.

## Two keyless MCP servers price some routes, but not the demo routes

No operator in scope offers a fare API. **Tallink Silja, Viking Line and Eckerö Line have no public API.** Tallink lists only a partner email address ([Tallink contacts](https://tallink.com/good-to-know/contacts)). VR offers travel agencies website booking and "collaboration agreements", not an API ([VR for travel agencies](https://www.vr.fi/en/for-travel-agencies)). CP's official GTFS feed contains schedules but **no fare files** ([CP GTFS](https://publico.cp.pt/gtfs/gtfs.zip)), and its prices are published as PDFs ([CP Alfa Pendular prices](https://cp.pt/info/prices-alfa-pendular)). Transitous returned seven Lisbon→Porto itineraries without a single fare field ([Transitous API](https://api.transitous.org/api/v4/plan?fromPlace=38.7139,-9.1394&toPlace=41.1496,-8.6109&time=2026-12-10T08:00:00Z)). The aggregators are closed to students. Trainline needs a commercial agreement and an integration of roughly 12 weeks ([AltexSoft](https://www.altexsoft.com/blog/business/rail-booking-apis/)). Distribusion hands out demo keys only by email ([Distribusion docs](https://docs.distribusion.com/dt/api/getting-started/intro)). Rome2Rio's API states it "does not provide live transit prices" ([Rome2Rio API docs](https://cms.rome2rio.com/documentation/1-4/search)). The Kiwi MCP the planner already uses searches flights only ([Smithery Kiwi](https://smithery.ai/server/kiwi)).

Two official servers do return prices with no key, so the planner gains something at zero cost. **Virail's MCP** (`https://virail.ai/mcp`, "No install, no API key") covers trains, buses, ferries and flights across Europe ([GitHub viraildev/virail-mcp](https://github.com/viraildev/virail-mcp)). In a live test it returned **five FlixBus Helsinki→Tallinn options at €40.98** with AWIN affiliate booking links. However, **only 2 of 9 searches returned data**: Lisbon→Porto, Helsinki→Tampere and Munich→Berlin each came back as an empty stream after about 10 seconds ([virail.ai/mcp](https://virail.ai/mcp)). The €40.98 product is bus plus ferry, roughly double a foot-passenger ferry ticket, so the planner must not label it "the ferry price". **Ferryhopper's MCP** (`https://mcp.ferryhopper.com/mcp`) worked with no key. It returned Piraeus→Mykonos at €53 (deck) and €58 (seat) in structured cents fields ([fh-mcp docs](https://ferryhopper.github.io/fh-mcp/); [mcp.ferryhopper.com](https://mcp.ferryhopper.com/mcp)). It recognises Helsinki→Tallinn as a connection, yet returned **"Found 0 itineraries" on every Baltic date tested**, even though ferryhopper.com sells the route from about €11 (Viking Line), €14.40 (Tallink Silja) and €21.50 (Eckerö) for December 2026 ([Ferryhopper Helsinki–Tallinn](https://www.ferryhopper.com/en/ferry-routes/direct/helsinki-tallinn)). That route page also says fares start "around €17", which contradicts its own fare list. The Baltic gap could be a port-resolver bug or a missing supplier; it was not tested further.

The remaining routes to fares fail the legal test. The `public-transport/flix` client returns FlixBus prices with a built-in key, but its README says "Ask them for permission" before production use ([GitHub flix](https://github.com/public-transport/flix)). `db-vendo-client` warns of "haphazard blocking" and says "strictly speaking, permission is necessary" ([GitHub db-vendo-client](https://github.com/public-transport/db-vendo-client)). The official FlixBus API requires a partner application through AWIN ([FlixBus affiliate partners](https://www.flixbus.co.uk/company/partners/affiliate-partners)). One open fare source does exist: **HSL's GTFS feed carries zone fares** such as AB €3.30 and ABC €4.50 ([HSL GTFS](https://infopalvelut.storage.hsldev.com/gtfs/hsl.zip)). It is useful for getting around Helsinki locally, not for intercity trips. For this gap, **web search remains the best source for Helsinki–Tallinn ferries and for VR and CP rail**. The two MCPs go in front of it because they cost nothing and sometimes win.

## Wikivoyage and Wikidata beat search for traditional dishes

This is the one gap where free sources clearly outperform Tavily for all three countries. **Wikivoyage country "Eat" sections name the canonical dishes in a few kilobytes of traveller-curated text.** For Portugal: caldo verde, bacalhau à Brás, sardinhas assadas, cozido à portuguesa and pastel de nata ([Wikivoyage Portugal#Eat](https://en.wikivoyage.org/w/api.php?action=parse&page=Portugal&prop=wikitext&section=44)). For Estonia: "The closest thing to a national dish is *verivorst*", served with lingonberry jam and *mulgikapsad* ([Wikivoyage Estonia#Eat](https://en.wikivoyage.org/wiki/Estonia#Eat)). The Finland section is 15,576 characters long and contains 72 italicised terms, including kalakukko, ruisleipä and lihapiirakka ([Wikivoyage Finland#Eat](https://en.wikivoyage.org/wiki/Finland#Eat)). City pages are the weak spot: Lisbon#Eat lists neighbourhoods and Tallinn#Eat lists restaurants, not dishes ([Wikivoyage API](https://en.wikivoyage.org/w/api.php?action=parse&page=Lisbon&prop=sections)). The planner should therefore resolve a city to its country before calling.

**Wikidata adds structure, but naive queries miss the most famous dishes.** A query on "instance of dish + country of origin" finds only 2 dishes for Estonia, 10 for Portugal and 15 for Finland. The reason is inconsistent modelling: caldo verde, bifana, mämmi and mulgipuder have no "instance of" statement at all ([Wikidata API](https://www.wikidata.org/w/api.php?action=query&list=search&srsearch=haswbstatement:P2012=Q1069518)). The broader query in the notes works much better. It takes the union of country of origin (P495), cuisine (P2012) and part-of-cuisine (P361), restricts to subclasses of food, removes restaurants and ranks by sitelink count. It returned **194 items for Portugal, 26 for Estonia and 117 for Finland**, most with English descriptions and Commons images ([QLever](https://qlever.dev/api/wikidata)). Two caveats remain. The results still mix in drinks and brands such as Viru Valge and Dynami:t, and Estonia still lacks verivorst. So Wikidata should enrich the Wikivoyage list, not replace it. On speed, the official WDQS endpoint took 24–40 seconds against a 60-second limit, and one call returned 429 "Aggressively rate-limiting to 1 req / min" during an outage. The QLever mirror answered the same query in 3.6–10.6 seconds ([WDQS User Manual](https://www.mediawiki.org/wiki/Wikidata_Query_Service/User_Manual)).

Wikipedia is a third layer. "List of Portuguese dishes" has **270 bulleted wikilinks** in its first section alone, which are easy to regex out ([Wikipedia API](https://en.wikipedia.org/w/api.php?action=parse&page=List_of_Portuguese_dishes&prop=sections)). Estonia and Finland have no list page, but their cuisine articles wikilink dish names, for example "*Mulgipuder* is the only Estonian national food that is in the UNESCO List" ([Wikipedia: Estonian cuisine](https://en.wikipedia.org/wiki/Estonian_cuisine)). The official **Wikidata MCP** (`https://wd-mcp.wmcloud.org/mcp/`) connected with no auth and offers an `execute_sparql` tool ([Wikidata:MCP](https://www.wikidata.org/wiki/Wikidata:MCP)). Its keyword search mixed relevant dishes with sheep breeds and glacial boulders ([Wikidata MCP endpoint](https://wd-mcp.wmcloud.org/mcp/)), so a fixed Python function tool is more testable. Recipe APIs lose this gap. **TheMealDB has 8 Portuguese meals and zero Estonian or Finnish ones** ([TheMealDB](https://www.themealdb.com/api/json/v1/1/filter.php?a=Portuguese)). Edamam is paid only and offers just "nordic" and "eastern europe" as cuisine types ([Edamam docs](https://developer.edamam.com/edamam-docs-recipe-api)). Spoonacular's free tier requires a backlink and deleting cached data after one hour ([Spoonacular pricing](https://spoonacular.com/food-api/pricing)). One operational requirement applies to every Wikimedia call: Wikimedia's 2026 limits give **10 req/min to clients identified only by IP and 200 req/min to bots with a contact-bearing User-Agent** ([Wikimedia APIs/Rate limits](https://www.mediawiki.org/wiki/Wikimedia_APIs/Rate_limits)). The researchers were throttled with a contact-less User-Agent.

## OSM covers museum hours; ticket prices still need the official site

**OSM is surprisingly good for museums and poor for everything else.** Counted inside each city boundary, `opening_hours` is filled on **66% of Lisbon's 104 museums, 82% of Tallinn's 67 and 63% of Helsinki's 49**, and `fee` (yes/no) on 63–71%. For viewpoints and `historic=*` objects, fill rates drop to 0–15% ([QLever OSM planet](https://qlever.cs.uni-freiburg.de/osm-planet)). Flagships are well covered. Jerónimos carries a full seasonal string with holiday closures, and Kumu, the Kadriorg Art Museum and the Seaplane Harbour all have hours. The actual price tag `charge` is nearly empty, though: 27% in Lisbon and a single value in each of the other two cities. Some values are non-standard ("Closed until 2027"), so a strict parser will reject them. `opening_hours_py`, a Python binding of the Rust `opening-hours-rs` crate, can parse the syntax and answer "open Tuesday 10:00?" ([PyPI opening_hours_py](https://pypi.org/project/opening-hours-py/)). One reliability warning applies: the public Overpass endpoints timed out during this research after one successful query, so the existing Overpass client needs a timeout and a mirror fallback.

**Helsinki has the best municipal source.** The city's Hauki API returned day-by-day hours for Helsinki City Museum with no key ([Hauki API](https://hauki.api.hel.fi/v1/)). Servicemap v2 adds holiday exceptions such as closures on 6 and 24–25 December ([Servicemap API](https://api.hel.fi/servicemap/v2/)). Coverage is limited to city-run venues: the state-run Ateneum returned no hours. The old MyHelsinki Open API did not respond and should be treated as discontinued ([HRI](https://hri.fi/en_gb/open-data-about-sights-and-activities-in-helsinki/)). Lisbon's CKAN portal and Visit Tallinn offer no comparable dataset ([Lisboa Aberta](https://lisboaaberta.cm-lisboa.pt/)). Wikidata has the right properties (P3025 open days, P2555 fee), but **none of nine flagship sights checked has hours or fee statements**. It does carry the P856 official website for most of them ([Wikidata Q272781](https://www.wikidata.org/wiki/Q272781)). This is the most useful route to prices: P856 gives the URL, and the agent fetches the museum's own page. That is more authoritative than a generic Tavily query.

**No commercial POI API returns admission prices.** Google Places has the best hours coverage, but `regularOpeningHours` triggers the Enterprise SKU (1,000 free calls per month, billing required) and Places has no ticket-price field ([Place Data Fields](https://developers.google.com/maps/documentation/places/web-service/data-fields)). TomTom Freemium gives **2,500 requests per day with no card**, and Place by ID returns hours for the next seven days ([TomTom pricing](https://developer.tomtom.com/pricing); [TomTom Place by ID](https://developer.tomtom.com/search-api/search-api-documentation/place-id)). Its coverage for the three cities is unverified. Geoapify only re-serves OSM ([Geoapify Place Details](https://apidocs.geoapify.com/docs/place-details/)). The only structured price source is ticket resellers. **Viator's Basic access is "instant self-service" with "no prior approval"** and includes product pricing ([Viator levels of access](https://partnerresources.viator.com/travel-commerce/levels-of-access/)). Its prices are reseller "from" prices, often for bundles, not the gate price. Tiqets requires an eligibility review ([Tiqets API program](https://www.tiqets.com/en/partner-program/api-program/)), and GetYourGuide forbids caching ([GYG partner-api-spec](https://github.com/getyourguide/partner-api-spec)).

## Restaurant ratings stay behind a billing account

**Foursquare's failure was structural, not a quota accident.** `price` and `rating` are Premium fields, and Premium calls have no free band: $18.75 per thousand from the first call ([Foursquare response fields](https://docs.foursquare.com/fsq-developers-places/reference/response-fields); [Foursquare pricing](https://foursquare.com/pricing/)). Other providers are no better. Yelp has no free tier ($229 per month after a 30-day trial) and no Estonia locale ([Yelp Places API](https://business.yelp.com/data/products/places-api/); [Yelp locales](https://docs.developer.yelp.com/docs/resources-supported-locales)). TheFork is partner-only ([DM Champ](https://help.dmchamp.com/integrations/thefork/)). OSM has effectively no price data: `price_range` is used **6 times worldwide** ([taginfo](https://taginfo.openstreetmap.org/api/4/key/stats?key=price_range)). OSM tags can still serve as budget proxies: `amenity=fast_food` and chain `brand=*` mean budget, and `award:michelin` means splurge.

Two no-card sources add real price tiers. **Wikivoyage district pages for Lisbon have Budget / Mid-range / Splurge sections** (Alfama, Bairro Alto), even though the Lisbon city page has none ([Wikivoyage API: Lisbon/Alfama](https://en.wikivoyage.org/w/api.php?action=parse&page=Lisbon/Alfama&prop=sections&format=json)). The community **michelin-my-maps CSV**, last updated 3 November 2026, gives `$`–`$$$$` price tiers and awards for **42 Lisbon, 32 Tallinn and 29 Helsinki restaurants** ([GitHub michelin-my-maps](https://github.com/ngshiheng/michelin-my-maps)). It leans upscale and is scraped from the Michelin Guide website, and its README limits use to "research purposes". The developer should treat it as a ToS grey area: fine for a student demo with attribution, wrong for redistribution.

### The Tripadvisor disagreement resolves against Tripadvisor

The sights note lists Tripadvisor at "5,000 calls/month free, credit card required". That figure comes from the **legacy** Content API FAQ ([Tripadvisor Content API FAQ](https://tripadvisor-content-api.readme.io/reference/faq)). The restaurant note cites Tripadvisor's newer Terra migration FAQ, which states: "The legacy Content API will be sunset and API keys deprecated on **August 31, 2026**". It also states that the 5,000-call tier "was a legacy Content API offering" ([Terra Migration FAQ](https://docs.terra.tripadvisor.com/docs/faq.md)). This report is dated 17 November 2026, so the more specific and more recent Terra claim governs, and the 5,000-call figure is obsolete. Terra Discover grants the **first 1,000 billable entities once per account lifetime**, then charges $0.009–$0.015 per entity ([Terra pricing](https://docs.terra.tripadvisor.com/docs/usage-based-pricing.md)). A 10-result nearby search uses 10 entities, so the free grant covers about 100 searches in total. The terms also forbid caching, forbid combining content with other sources and forbid re-sorting. They allow AI use only for "internal … non-commercial" RAG grounding ([Terra Master Terms](https://docs.terra.tripadvisor.com/docs/api-master-terms)). A multi-agent planner that merges and ranks restaurants breaks the content and ranking clauses outright. The community `pab1it0/tripadvisor-mcp` targets the dead legacy keys ([pab1it0 README](https://cdn.jsdelivr.net/gh/pab1it0/tripadvisor-mcp@main/README.md)).

**Google is the only full-coverage option, and it needs a card.** Text Search Enterprise returns `priceLevel`, `priceRange`, `rating` and `userRatingCount`, supports a `priceLevels` filter, and includes 1,000 free calls per month before $35 per thousand ([Places usage and billing](https://developers.google.com/maps/documentation/places/web-service/usage-and-billing); [Google pricing](https://developers.google.com/maps/billing-and-pricing/pricing)). The terms allow storing only place IDs, and Google attribution is mandatory ([Places policies](https://developers.google.com/maps/documentation/places/web-service/policies)). The no-billing **Maps Demo Key** supports Places (New) but is "not designed for production use" and excludes "user-generated content". The docs do not say whether aggregate ratings count as user-generated content, which a live test would settle ([Maps Demo Key](https://developers.google.com/maps/demo-key)). Google's official **Maps Experience agent tools MCP** (`mapstools.googleapis.com/mcp`) gives 10,000 free requests per month. It returns a prose summary plus place IDs, not structured rating fields ([Maps Experience agent tools](https://developers.google.com/maps/ai/grounding-lite)). That is fine for discovery but unreliable for a budget filter. **Without a card, web search remains the best source of ratings.**

## Implementation plan: four tools, Tavily last

The table below gives the order in which each tool should run. Every option in it needs neither a credit card nor partner approval, except Viator, whose card requirement is unconfirmed.

| Gap | 1st | 2nd | 3rd | Tavily role |
|---|---|---|---|---|
| Train/bus/ferry fares | Virail MCP (`virail.ai/mcp`, timeout ≥15 s) | Ferryhopper MCP (Mediterranean/Iberian ferries; skip for Baltic) | Static "indicative" table: HEL–TLL ferry about €11–€22 from Ferryhopper's December fares; CP fares from published price tables; HSL zone fares from GTFS | **Stays primary for HEL–TLL ferries and VR/CP rail**, scoped to operator or Ferryhopper pages, with booking deep link |
| Traditional dishes | Wikivoyage country "Eat" section through the existing MediaWiki client, with an LLM extracting 5–8 dishes | Wikidata SPARQL union query (QLever, WDQS fallback), ranked by sitelinks, with drinks and brands filtered out, for names, descriptions and images | Wikipedia "List of Portuguese dishes" or the cuisine article | **Drop**, except optional city-level colour |
| Sight hours and tickets | OSM `opening_hours`/`fee`/`charge` through the existing Overpass client, parsed with `opening_hours_py` | Helsinki only: Servicemap search → Hauki hours for the trip dates | Wikidata P856 → fetch the official site for prices and hours; optionally Viator Basic for "tickets from €X" | **Last resort**, mainly for prices |
| Restaurants (price/rating) | Wikivoyage Eat tiers (city page, then district pages for Lisbon) | Michelin CSV (bundled, attributed, research-only) | OSM heuristics (fast_food, brand, award:michelin) | **Stays the only free source of ratings** |

The second table lists the options that need a card or billing account. Each is an opt-in upgrade, ordered by value to this planner.

| Option | Fills | Free allowance | Caveats |
|---|---|---|---|
| Google Places (New), Text Search/Place Details Enterprise | Restaurant price + rating; sight hours | 1,000 calls/month per Enterprise SKU | Store place IDs only; attribution required; set a budget alert ([Google pricing](https://developers.google.com/maps/billing-and-pricing/pricing)) |
| Google Maps Experience agent tools MCP | Discovery, prose summaries | 10,000/month Essentials (also usable with the no-billing Demo Key for prototyping) | No structured rating fields |
| Mapbox Search Box | `rating` and `price_levels` "if available" | 25,000 requests/month | Card likely (unverified); EU fill rate untested ([Mapbox Search Box](https://docs.mapbox.com/api/search/search-box/)) |
| HERE Search | Some hours | 30,000/month | Card required; "Limited plan" retired ([HERE KB](https://docs.here.com/here-kb/docs/can-i-switch-from-here-base-plan-to-here-limited-plan)) |
| Tripadvisor Terra Discover | Rating, price level, hours | 1,000 entities lifetime | Bans caching, merging and re-ranking; AI use limited; **do not adopt** |
| Yelp, Foursquare Premium, Gemini Maps grounding | Rating/price | Trial only / none / paid tier only | Not worth it here |

Both MCP servers can be attached in ADK as `McpToolset`s over streamable HTTP, or called with a plain `httpx` JSON-RPC POST using `Accept: application/json, text/event-stream`. The dish and hours tools work best as deterministic Python function tools with per-country caching. All Wikimedia calls need a User-Agent that includes a project URL or contact address.

## Conclusion

The four gaps split along one line: whether the data is curated by a community or sold by a business. Dishes and museum hours are community knowledge that Wikimedia and OSM already publish openly, so the planner can drop most Tavily calls there today. Fares and ratings are the inventory and reviews that operators and platforms monetise, and that is why every free path there is flaky, restricted or partner-gated. The new agent-facing MCPs (Virail, Ferryhopper, Google Maps, Wikidata) lower the integration cost, but they do not change who owns the data: an MCP server inherits its backend's coverage and terms.

Three cheap live tests would settle the remaining unknowns: whether the Maps Demo Key returns `rating` and `priceLevel`, whether Ferryhopper's MCP accepts exact Baltic port names, and whether Virail's empty responses are timeouts or coverage gaps. Two of them could move Helsinki–Tallinn ferry prices from web search to a structured tool. The Demo Key test would show whether Google restaurant ratings are reachable without a card.
